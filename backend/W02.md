# W02 — persistance des séances personnelles

Source : Sprint 2, S2-US4 / W02. Schéma de Lamia inchangé.

## Implémentation

POST /api/activities exige session et CSRF, valide le JSON Sprint 1 et conserve
HTTP 202 / {"status":"ACCEPTED","message":"Activite recue et validee"} après
saveAndFlush réussi. L'identité vient exclusivement de Spring Security.
ActivityService résout le compte via AccountStore ; aucun memberId client utilisé.
PostgresOwnedActivityStore charge ce compte, puis insère une nouvelle Activity
avec son propriétaire dans la même transaction. Pas de repli sur une insertion
sans propriétaire. ID nul ou compte absent : 401 ; adaptateur absent : 503.

## Mapping exact

| Colonne public.activities | Java Activity |
|---|---|
| id (Sprint 1) | Long id, IDENTITY |
| equipment_type (Sprint 1) | String equipmentType, longueur 50 |
| duration_minutes (Sprint 1) | Integer durationMinutes |
| distance_km (Sprint 1) | Double distanceKm |
| date (Sprint 1) | LocalDateTime date |
| adherent_id BIGINT NULL | Adherent adherent, ManyToOne LAZY optional=true |

JoinColumn adherent_id, contrainte activities_adherent_fk vers public.adherents(id),
ON DELETE RESTRICT dans le SQL. L'index activities_adherent_date_idx est fourni
par Lamia. La référence est exclue de JSON : aucune fuite du compte/hash ni
chargement paresseux lors de la sérialisation du contrat Sprint 1.
La colonne equipment_id est volontairement laissée hors du mapping W02 :
les nouvelles insertions la laissent à NULL ; aucune gestion d'équipement ajoutée.

Les anciennes activités restent lisibles avec adherent=null. Le constructeur
sans propriétaire est conservé pour le modèle historique et les fixtures de test ;
il n'est jamais utilisé par le chemin de création API. Aucune mise à jour ou
attribution automatique de l'historique. Le GET reste global : W03 n'est pas commencé.
L'exclusion des historiques non attribués des futures vues personnelles relève de W03.
Aucun frontend ni simulateur Python modifié.
